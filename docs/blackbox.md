# Формат записи поведения КСГ

Выгрузка JSONL содержит запись `record_type=session`, затем события `record_type=event`. Версия схемы: `aksg.behavior.v1`.

Сессия хранит идентификаторы пользователя и проекта, режим `human`, `test` или `api`, время начала, исходный график `initial_state` и исходное состояние интерфейса `initial_view`. Сессия пользователя в одной вкладке и проекте продолжается после обновления страницы.

Событие содержит:

| Поле | Значение |
| --- | --- |
| id | Уникальный UUID события; повторная доставка не создаёт дубликат |
| ordinal | Серверный порядок получения |
| client_seq | Порядок событий интерфейса в сессии |
| client_at / received_at | Время на клиенте и время получения сервером |
| action_id | Связь между намерением пользователя, серверным изменением и результатом |
| origin | client — событие интерфейса; server — подтверждённое изменение |
| kind | Например gesture, action.requested, task.update, action.succeeded, action.failed |
| observation | Выбранная работа, представление, масштаб, фильтр, прокрутка, размер окна и описание работ |
| payload | Семантика действия: поле, код работы, перенос в днях, параметры изменения и путь жеста |
| result | Результат выполнения или ошибка |
| before / after | Серверные снимки графика перед изменением и после него |

Для каждого изменения канонический снимок содержит работы с названиями, датами, длительностями, предшественниками, версиями и связями. При переносе и растягивании сохраняются также отсчёты жеста. Нажатия, выбор поля, завершённые правки полей, поиск, смена вида и масштаба, прокрутка и переключение видимости вкладки записываются как события интерфейса.

Запись не является видео экрана, записью паролей или глобальным перехватом клавиатуры. Сбор ограничен КСГ после входа. Ключи, похожие на password/token/cookie/secret/authorization/email/keystrokes, дополнительно отбрасываются сервером. События client не считаются доказательством изменения БД: для восстановления результата используются события server.

Механизм доставки: IndexedDB → пакетная отправка → подтверждение UUID → удаление из локальной очереди. При ошибке доставки очередь остаётся; после возобновления работы отправляются неприсланные события этого пользователя, включая предыдущие сессии. Пользователю показывается ошибка записи. Последние события при принудительном завершении браузера до фиксации локальной транзакции не гарантируются; искусственное отключение сети в браузерной приёмке пока не проверялось.

Работы записываются в той же PostgreSQL-транзакции, что и серверное событие с before/after. API не предоставляет редактирование и удаление событий. Экспорт доступен владельцу сессии; администратор проекта может читать сессии своего проекта. Чужие проекты и пользовательские сессии защищены серверными проверками.

Для подготовки обучающих эпизодов: отбирать проверенные пользовательские сессии, исключать `mode=test`, связывать события по action_id, отделять неуспешные попытки от успешных, восстанавливать исходное состояние и проверять серверный результат. Обучение, оценка модели и назначение экспертных меток остаются следующим этапом.
