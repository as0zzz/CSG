# АКСГ Центр управления строительством

Локальный демонстрационный прототип для ручного ведения КСГ и удалённой проверки материалов строительства железнодорожной инфраструктуры. Проект реализован по `docs/implementation-prompt.md`. Данные, организации, изображения и видео демонстрационного проекта вымышленные.

## Запуск на Windows

Требуется запущенный Docker Desktop с Linux containers и Docker Compose. В PowerShell из папки проекта:

```powershell
.\scripts\init-env.ps1
docker compose up -d --build
docker compose ps
```

Первый запуск скачивает образы и собирает MinIO из официального исходного кода. Это существенно дольше последующих запусков. При старте API автоматически применяет миграции и идемпотентный seed: существующие данные не перезаписываются.

- Приложение: http://localhost:8080
- API Swagger: http://localhost:8080/docs
- Состояние API: http://localhost:8080/api/health

Публикуется только порт `127.0.0.1:8080`. База, API и хранилище доступны внутри Docker network.

## Демонстрационные пользователи

Пароль всех начальных демопользователей — значение `DEMO_PASSWORD` в локальном `.env`. Скрипт генерирует случайный пароль вместе с отдельными секретами БД, S3 и сессии. `.env` исключён из Git. Профиль на экране входа заполняет только email; пароль требуется ввести.

| Email | Роль |
| --- | --- |
| planner@demo.local | Планировщик |
| inspector@demo.local | Удалённый инспектор |
| customer@demo.local | Заказчик, только чтение |
| admin@demo.local | Администратор без права редактирования КСГ |
| contractor@demo.local | Представитель первого подрядчика |
| other@demo.local | Пользователь второго изолированного проекта |
| outsider@demo.local | Пользователь без проектного доступа |

Назначение нескольких ролей доступно администратору на странице настроек. Для добавления существующего пользователя в проект используется его email. Новые проекты создаются из настроек; для начала работы администратор добавляет ось, подрядчика и участников. Управление учётными записями вне демопрофилей не входит в прототип.

## Основной сценарий

1. Войти как Planner, открыть КСГ и создать линейную работу. Выбрать ось и путь, задать отметки в метрах, плановый объём, единицу и даты.
2. Войти как RemoteInspector. При необходимости загрузить фото или видео в разделе «Материалы». На странице инспектора выбрать работу и материал, указать проверенный диапазон, дополнительный объём, время наблюдения и заключение. Для видео задать отметку/фрагмент.
3. Сохранить проверку: принятый объём и статус работы не изменятся.
4. Войти как Planner. В журнале проверок нажать «Принять объём» и указать причину. Повторное применение одной проверки запрещено сервером. Даты и статус автоматически не меняются.
5. Войти как CustomerViewer и проверить график, материалы и журнал. Завершение работы оформляет Planner отдельно, когда принят весь плановый объём и указаны фактические даты.

Корректировка факта записывается отдельной дельтой с причиной. Проверка не редактируется: кнопка «Уточнить» создаёт новую запись. Уточнение применённой проверки показывает необходимость пересмотра; факт автоматически не отменяется.

## Команды эксплуатации

```powershell
docker compose logs --tail 100 api
docker compose stop
docker compose start
docker compose exec api python -m app.seed
docker compose exec api python -m app.test_runner
```

Обычная остановка сохраняет данные. БД находится в volume `csg_postgres_data`, материалы — `csg_media_data` при запуске из папки CSG без переопределения имени Compose-проекта.

Полный сброс локальных демоданных выполняется **только по отдельному намерению пользователя**. Следующая команда удаляет все данные этого Compose-проекта, включая пользовательские изменения и материалы:

```powershell
docker compose down --volumes
docker compose up -d
```

После сброса seed создаётся заново. `DEMO_BASE_DATE` задаёт опорную дату первоначального заполнения; повторный seed её не переносит. Изменение `DEMO_PASSWORD` после заполнения не меняет хеши существующих пользователей.

## Проверки разработки

Backend проверяется в отдельной временной PostgreSQL-базе с именем `aksg_test_<uuid>`; тестовая база удаляется после запуска. Основная БД не очищается. Тестовые медиа имеют отдельные UUID проекта в общем приватном bucket; автоматическое удаление объектов не применяется.

```powershell
docker compose exec api python -m app.test_runner
cd frontend
npm ci
npm run typecheck
npm run lint
npm run build
```

Для установки frontend-зависимостей вне Docker нужен Node.js с npm. Сервер разработки `npm run dev` проксирует `/api` на localhost:8000, если API запущен разработчиком на этом порту; штатный полностью настроенный запуск — через Compose на 8080.

## Устройство проекта

- `backend/app/models.py` — реляционная модель и ограничения уникальности.
- `backend/app/schemas.py` — входные контракты.
- `backend/app/security.py` — пароли, сессии и проектные роли.
- `backend/app/services.py` — валидация, граф зависимостей и аудит.
- `backend/app/main.py` — REST API, защищённое медиа и симулятор.
- `backend/alembic` — миграции PostgreSQL/PostGIS.
- `backend/tests` — API-тесты бизнес-инвариантов и доступа.
- `backend/requirements.lock` — зафиксированные прямые и транзитивные Python-зависимости для Docker-сборки.
- `frontend/src` — интерфейс React/TypeScript.
- `storage/Dockerfile` — воспроизводимая сборка MinIO.
- `docs/scope.md`, `docs/decisions.md`, `docs/acceptance.md` — границы, решения и результаты проверок.

## Ограничения

Живые камеры, реальные GNSS, ML и автоматический пересчёт графика не подключаются. Линейная шкала не является геодезическим преобразованием. Аудит защищён от изменения через приложение; администратор БД обладает техническим доступом. Контрольная сумма медиа не доказывает подлинность съёмки. Прототип предназначен для локальной демонстрации процесса.
