# Принятые решения

1. Локальный Compose: UI/nginx, FastAPI, PostgreSQL 16/PostGIS и MinIO. Только web доступен на loopback. Облачные ресурсы не создаются.
2. Исходные публичные MinIO-образы больше не скачались из Docker Hub и Quay. Используется сборка официальной ревизии `7aac2a2c5b7c882e68c1ce017d8256be2feea27f`; исходник и лицензия доступны в образе сборки и исходном upstream. Основание: https://github.com/minio/minio (раздел Source-Only Distribution). Это сохраняет компонент исходного задания.
3. Объёмы хранятся decimal(14,3). Факт — сумма неизменяемых записей Progress. Применение проверки и исправление факта блокируют работу через SELECT FOR UPDATE; дополнительно inspection_id имеет UNIQUE. Граф зависимостей сериализуется блокировкой проекта.
4. Версия работы увеличивается при редактировании и изменении принятого факта. Старая версия отклоняется HTTP 409. Даты связанных работ автоматически не меняются.
5. Материалы выдаются backend по сессии с проверкой проекта и прав; поддержан Range. Подрядчик видит материал только при явном разрешении и связи с его работой. S3 напрямую браузеру недоступен.
6. Пароли PBKDF2 SHA-256 с индивидуальной солью. Сессия подписана, HttpOnly, SameSite=Strict; изменяющие запросы с чужого Origin отклоняются. Локальный HTTP используется только на loopback.
7. Инспекторская запись сохраняется целиком; уточнение создаёт новую связанную запись. Исправление ранее принятого факта остаётся решением Planner. Автоматического снятия объёмов нет.
8. Телеметрия создаётся внутренним таймером каждые 3 секунды по определённому маршруту. Остановка не меняет время последней точки. Сброс обнуляет шаг следующего воспроизведения и сохраняет исторические точки.
9. Объект, закреплённый за проверкой, нельзя удалить/архивировать через API. Сроки хранения и автоматическое удаление для промышленной эксплуатации пока не реализованы.
10. Времена наблюдений и аудита сохраняются с часовым поясом/UTC; UI показывает события в Europe/Moscow, форма наблюдения явно подписана UTC. Календарные даты хранятся отдельно.
11. Внешние шрифты, карты и аналитика не подключаются. Для интерфейса используются локальные системные шрифты. Демоизображения и ролик создаются при seed локальными Pillow и ffmpeg.
12. Первичная миграция создаёт схему из декларативной модели. Для дальнейшего развития нужно добавлять новые ревизии Alembic; изменения модели сами по себе не обновляют существующую БД.
13. Прямые и транзитивные Python-зависимости зафиксированы в requirements.lock; Docker использует этот lock-файл. Frontend использует package-lock.json. Vite обновлён до 6.4.6 после проверки npm audit. Итоговый web-образ содержит только nginx и статические файлы.
